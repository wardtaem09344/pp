# APEX Agent: تقرير التسليم وحالة التشغيل

تاريخ التقرير: 23 أكتوبر 2026. هذه نسخة تطوير فعلية مبنية على المستودع `wardtaem09344/mmm`، وليست إعلانًا عن اكتمال كل قدرات الوكيل العام أو جاهزية الإنتاج.

## ما تغيّر

- أُبقي أرشيف الواجهة الأصلي دون تعديل، وأُخرجت ملفات التطبيق إلى `app/`.
- أُنشئ خادم FastAPI للحسابات والجلسات والمحادثات والملفات والصلاحيات وإدارة الخطط.
- أُضيفت قيود Free وPlus وPro وUltra في الخادم، تشمل الاستخدام اليومي والنماذج والأدوات والخطوات والتزامن والملفات والسياق والذاكرة والاستئناف. تعيين الخطط للمالك؛ الدفع الإلكتروني غير موصول.
- أُضيف تصنيف متعدد المجالات واختيار استراتيجية وسير عمل بحسب المهمة، بدل فرض خطوات ثابتة على كل طلب.
- أُضيف تنفيذ فعلي لأدوات الحساب وملفات مساحة المهمة والتحقق الأساسي، ومخطط تبعيات محفوظ يرتبط بأدلة الأدوات. الاسترجاع الشبكي محدود بقائمة نطاقات مسموحة؛ البحث يحتاج إعداد خدمة حقيقية.
- أُضيفت نقاط استئناف وأحداث تنفيذ وإلغاء وواجهة لمراقبة المهام وذاكرة اختيارية معزولة لكل مستخدم.
- أُضيفت محوّلات Gemini وai-seek ومزوّد متوافق مع OpenAI، مع فصل تهيئة الاتصال عن إثبات نجاحه.
- أُضيفت ملفات تشغيل Docker وVercel واختبارات وتوثيق للمعمارية.

## النماذج: ما ثبت وما لم يثبت

محوّل Gemini يدعم جلب كتالوج نماذج توليد النصوص من واجهة الخدمة عند توفير اعتماد صالح. نجاح الكود في الاختبارات لا يثبت أن مفتاح المستخدم صالح أو أن كل نموذج مدرج متاح لحسابه.

قائمة ai-seek تتضمن الأسماء السبعة الواردة في تكامل المستخدم، وتعرضها باعتبارها مرشحات مقدمة منه، لا قائمة شاملة مكتشفة من المزوّد. لم يُقدَّم مسار موثّق لكتالوج هذه الخدمة؛ المسار المرشح الذي جُرّب أعاد 404.

الاختبار الحي عبر الاعتماد المحفوظ أعاد 401 مع رسالة تفيد بغياب access token. بيانات الاعتماد المحفوظة حاليًا تستخدم توثيق Bearer، بينما التكامل المقدم يتطلب ترويسة `x-access-token`؛ طُلب التصحيح عبر الإدخال الآمن، ولم يُثبت اتصال ناجح بعد.

لا توجد أسرار المستخدم في المصدر أو حزمة التسليم. لا تُنقل مفاتيح الوكيل الآمنة الخاصة ببيئة التطوير إلى Vercel؛ يحتاج الإنتاج تهيئة مستقلة آمنة.

## التحقق المنفّذ

- نجح تشغيل `python -m pytest -q`: عدد 62 اختبارًا على Python 3.11 و3.14 بعد تحديث الاعتماديات.
- تشمل الاختبارات العزل بين الحسابات، وحماية المالك، وحصص الخطط، وسلامة المسارات، والتنفيذ الفعلي لأدوات الملفات والحساب، ومخططات التبعيات، وحفظ الرسائل والأحداث، وبروتوكولات المزوّدين.
- اختبارات المزوّدين تستخدم استجابات محلية حتمية للاختبار فقط؛ لا تستبدل النماذج في التطبيق ولا تثبت جودة الذكاء الاصطناعي أو نجاح اتصال حي.
- فحص `pip-audit` بعد التحديث: 22 اعتمادية، دون تنبيهات ثغرات معروفة وقت الفحص. هذا فحص للاعتماديات وليس شهادة أمان شاملة.
- فحص ميكانيكي لأنماط الأسرار في ملفات التطبيق والخادم والاختبارات والتهيئة: لم يجد أسرارًا مطابقة للأنماط المفحوصة.
- فُحصت واجهة الكمبيوتر والهاتف، والتسجيل، والجلسة بعد التحديث، وعرض الخطط، وحجب وضع الوكيل عن Free، ورسائل غياب المزوّد، وتبديل اللغة والمظهر. تفاصيل تغطية الواجهة موجودة في `FLOWS.md`.
- فُتحت المعاينة المرفوعة في جلسة متصفح جديدة، ونجح إنشاء حساب اختبار وعرض الخطط والخروج، دون أخطاء صفحة JavaScript مرصودة.
- كشف تشغيل GitHub الأول سباقًا زمنيًا قد يفقد أحداث التحقق والإكمال عند إغلاق SSE؛ أُصلح السبب، وأصبح اختبار مسار الملفات يشترط وصول الحدثين. لا يُخلط هذا التصحيح مع إثبات اتصال نموذج حي.
- لم تكتمل المراجعة الأمنية المستقلة بسبب تعطل خدمة المراجع. لا تُعد هذه النسخة مجتازة لبوابة نشر إنتاجية مستقلة.

## حالة الاستضافة

أُنشئ مشروع Vercel باسم `mmm-apex-agent`، لكن عمليات النشر والاستعلام عن النشر رُفضت بخطأ صلاحيات 403. لم تكتمل إعادة تفويض اتصال Vercel؛ لذلك لا يوجد نشر إنتاج ناجح أو عنوان `vercel.app` متحقق منه.

المعاينة المرفقة تعرض التطبيق للتجربة، لكنها ليست بديلًا عن استضافة إنتاج دائمة. الخادم على Vercel يرفض تفعيل الحسابات والوكيل دون PostgreSQL دائم، بدل تخزين بيانات المستخدمين في SQLite مؤقتة.

## متطلبات الإكمال

- اعتماد صالح لـGemini في الإدخال الآمن، واعتماد ai-seek بترويسة `x-access-token` إن أُريد استخدام الخدمة.
- نجاح اختبار نصي حي لكل نموذج قبل وصفه بأنه متاح ومختبَر.
- قاعدة PostgreSQL دائمة ونسخ احتياطية؛ الاتصال المطلوب بقاعدة البيانات لم يكتمل بعد.
- صلاحية نشر صالحة على Vercel، أو اختيار استضافة أخرى معتمدة من المستخدم.
- إعداد أسرار الإنتاج على الخادم، ثم اختبار الحسابات والوكيل والملفات والحصص على الرابط النهائي في متصفح جديد.
- مراجعة أمان مستقلة قبل إعلان جاهزية الإنتاج.

## حدود مقصودة ومخاطر متبقية

- لا توجد أدوات shell أو متصفح مستقل أو عمال نماذج متوازون؛ لا تُعرض على أنها منفذة.
- التحقق من ملف HTML أساسي، وليس اختبار JavaScript أو متصفح أو إتاحة. نجاح الحساب أو تحليل JSON لا يثبت اكتمال الهدف كله.
- الاستئناف يستند إلى نقاط حفظ، ويمنع إعادة تشغيل بعض العمليات ذات النتيجة غير المؤكدة؛ لا يضمن تنفيذًا لا نهائيًا بعد انقطاع الخادم.
- الدردشة المؤقتة إخفاء ومحاولة حذف من الواجهة، وليست ضمان محو شامل؛ قد تبقى سجلات المهام والأدلة. يتطلب الإنتاج سياسة احتفاظ وحذف شاملة واختبارات لها.
- لا توجد معالجة فعلية للصور أو توليد صور، ولا تكامل دفع أو إرسال رسائل أو مشتريات أو صلاحيات نشر يمنحها النموذج لنفسه.
- التصنيف الحالي خط أساس قابل للقياس والتحسين، وليس إثباتًا لذكاء عام أو تحسن عددي في جودة النتائج.
